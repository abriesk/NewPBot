Admin user guide

For the therapist. How to run bookings from the web admin and from Telegram. The public site is /. Your console is /admin, in English. Clients may use Russian, Armenian, or English.

1. What the service does

Clients read practice information and request a consultation on the website or in the Telegram bot. When you are not taking people, they join a waitlist.

You stay in the loop unless you turn on auto-confirm:

Approve Propose another time Reject Cancel Waitlist: contacted / converted / closed

Email is outbound only. If SMTP was left empty at install, email is off and people sign in through Telegram.

2. First sign-in

  1. Open https://YOUR-DOMAIN/admin (or http://127.0.0.1:8000/admin on a local/plain install).
  2. Use the install username and password (ADMIN_USERNAME / ADMIN_PASSWORD).
  3. After first start the password is stored only as a hash.
Login is limited to 5 attempts per 15 minutes per IP. If you are locked out, wait.

Do this once before inviting clients

4. Daily workflow

  1. Open Requests. Filter by pending or negotiating.
  2. Open each new request. Read what they wrote (detail page only).
  3. Approve, propose another time, or reject.
  4. Before proposing a time of your own, switch to schedule and look at the week.
  5. Check Waitlist if availability is off.
  6. If someone missed a message, open Delivery.
  7. On the phone, send /admin to the bot.
Do not edit .env for ordinary practice changes. Availability, prices, reminders, content, and booking mode all live in the admin UI.

5. Requests

Two views of the same queue

list and schedule switch at the top of /admin/requests.

  • list — filterable by status. Click the short UUID for the detail page.
  • schedule — the week as a grid in the practice timezone, so you can see what a time collides with before you propose it. Arrows move a week at a time; this week comes back.

Under the grid, Unscheduled holds the requests with no instant to draw: someone who asked in words, and a slot request whose hold has since lapsed. They are listed rather than dropped — these are usually the ones most in need of an answer.

The list carries Name and Contact, because this is where you decide what to open. A name falls back to the client's remembered name, so a returning client is not blank just because they did not retype it. Each contact is a link: email opens your mail client, a Telegram id opens the chat where your own Telegram already knows that person and otherwise stays the plain id it always was.

pending → negotiating → confirmed → completed │ │ │ ├─ reject ├─ reject └─ cancel └─ expire └─ expire
StatusMeaning
pendingNew. Waiting for you.
negotiatingA time was proposed. Someone still has to accept.
confirmedBooked. Reminders will fire.
rejectedYou declined.
expiredNobody answered in time.
cancelledYou cancelled a booked session.

Clients cannot cancel themselves.

Detail page

Status, type, modality, name, scheduled and/or desired time, client timezone, contact note, negotiation thread, whose turn it is.

Reachable at lists the client's identities — often the only thing identifying a request booked from the web with no name. An email is marked verified or unverified: nothing is delivered to an unverified address, which is worth knowing before you spend a day waiting for a reply.

What they wrote (problem text) is only on this page — never in the list, logs, or email. Telegram shows it only to you.

Actions

Only the actions this status allows are live. The rest stay on the page, greyed, with a line saying why — so someone looking for Cancel learns that it is for confirmed sessions only, instead of hunting for a button that was removed.

Approve — from pending and from negotiating. Leave the time blank and it confirms the last time either side put forward; on a pending request, where nothing has been discussed, that is the slot the client picked. Naming a time still wins. Optional per-session meeting URL; otherwise the standing room from Settings is used for online sessions.

Propose — a time, a note, or both. A note with no time is a real move, not a mistake: the client is told there is a reply and sent to their request page to read it, and they can accept it there. Nothing can be scheduled out of words, so the request stays negotiating until one of you names a time — you are told when they accept.

Reject / Cancel — optional reason. Cancel stops reminders on a confirmed session. Cancel is not an alias for Reject: they send the client different messages.

A time this form cannot read flashes bad-time and changes nothing — nothing is sent, so retype it and submit again. An empty time field still means words only. If the status moved while the page was open, it flashes refused.

Where a booking stops being protected by the grid

A slot request holds its slot for as long as the conversation runs, and the hold is renewed at every move — yours and the client's. What happens to it depends on what you propose:

You proposeThe held slot
The time the client already pickedStays held for them
A note with no timeStays held — you have moved away from nothing
Any other timeGoes back on the picker; you have moved away from it

A client countering with another time does not release it either. Suggesting an alternative is not giving up on the slot they picked, and you may still approve that slot.

On Approve, the slot is booked only when it is the confirmed time. Settle on another time and it goes back for somebody else rather than being marked booked for a session that is not at it — and if the time you agreed happens to match a free slot of yours, that one comes off the picker instead.

A time you invent is guarded only if a free slot exists at that moment. If it does not, nothing stops you confirming a second client into the same hour later. The calendar cannot catch that for you, so check the schedule view before proposing a time that is not in your grid.

A negotiation where neither side has ever named a time cannot be approved with the field blank. The request may still hold the slot the client originally picked, but confirming that would tell them a time they never agreed to — so type the time you settled on.

6. Waitlist

People land here three ways:

  • Accepting new bookings is off.
  • Slot mode, no free slots, and fallback-to-negotiation off.
  • They could not make a time you proposed and had no other way to say so — no free slots and free text off. Declining and joining the list is one move, and the entry carries what they wrote and their contact note, so it does not arrive anonymous.
ActionMeaning
contactedYou reached out.
convertedThey booked, or you will book them by hand.
closedNo longer waiting.

A waitlist entry is not a booking: no slot, no negotiation, no reminders. Type an optional note, then press the action.

Fallback to negotiation gates the same thing one step later: it decides whether a client answering your proposal may name a time of their own. The Telegram picker sits behind the same switch — it is the free-text half in another shape, and turning words off must not leave the way in open. With it off and no free slots, their only replies are accept, decline, or join the waitlist.

Practice & timing

  • Timezone must be IANA, e.g. Asia/Yerevan — never UTC+4.
  • Default language ru / hy / en.
  • Clinic address link and standing meeting room. You can still override the meeting URL when approving.
  • Join links are not sent by email; email points at the request page.
  • Slot hold (minutes), pending expiry (hours), cancellation window, retention (months — free text is later cleared, rows stay).
  • Reminder offsets in minutes, comma-separated, e.g. 1440, 60. Empty = no reminders.

9. Session types

Seeded: individual and couple, both 60 minutes. Add more (e.g. supervision) without a software update.

  • Price (minor units) — smallest currency unit. AMD: 15000 = 15,000 dram. EUR/USD: 5000 = 50.00.
  • Currency — three letters (AMD, EUR…).
  • Uncheck active to hide a type from new bookings.
Do not rename a code later. Add a new type and deactivate the old one.

UI strings — buttons, errors, bot replies, emails — not the practice pages.

  • Grouped by where they appear. Save per row.
  • A software update never overwrites a string you already changed.

13. Delivery

One row = one outbound message. Status moves pending → sending → sent, or failed / dead.

dead means retries stopped. Check SMTP, or whether the user blocked the bot. Taking a new admin action queues a fresh message; dead rows are not resent from this page.

14. Clients and privacy

A client is the person. They may have Telegram and/or email identities — the client row is that grouping. Two pages read it, for two different jobs.

Clients — /admin/clients

The practice's people: everyone who has requested a consultation, most recent activity first, with how to reach them, how many requests they have made, and their last and next session. The name and the count both open that person's page — every request they have made, drawn as the same row the queue draws, and their waitlist entries.

Somebody who only ever asked for a sign-in link and never booked is not here. Neither is anybody erased. Both are on Privacy, whose list has to be complete.

Two identities that were never linked are still two rows. The service does not know they are one human; only the client can say so, by following the Telegram link their sign-in email already carries.

No problem text on either page. It stays one click away, on the request.

Privacy — /admin/privacy

Every client row there has ever been, unfiltered on purpose: “send me my data” and “forget me” can only be answered against the whole population, and a privacy page that filters is one with a hole in it. A client's page links to their row here.

Export downloads everything held about them, including what they wrote.

Erase is irreversible. Type the word erase, then confirm. Identities and tokens go; free text is cleared; confirmed sessions are cancelled so reminders stop; booking rows stay marked erased for statistics.

A retention job later clears problem text, negotiation bodies, and contact notes. Rows remain.

Problem text never appears in logs, emails, or the request list. Database dumps do contain it — treat backups as confidential. This is careful handling, not legal advice.

15. Maintenance

A. Configuration file — safe off-server

Export JSON: settings, session types, timezones, topics, blocks, translations. No client data. No slots.

Import merges: adds and updates named items, never deletes omitted ones. Preview first (writes nothing). Then choose the file again and Import. Bad content edits roll back from Revisions.

B. Database backups — confidential

Taken daily into the host backups/ folder. Download from this page. Includes problem text.

There is no “back up now” or “restore” button. Restore overwrites every booking since the dump — command line only, for whoever hosts the service.

16. Telegram admin

Your numeric Telegram user ID must be in TELEGRAM_ADMIN_IDS. Anyone else who types /admin gets silence.

Send /admin for the panel: availability, pending/negotiating counts, next session, waitlist count, link to the web UI.

Requests Sessions (2 or 7 days) Waitlist Availability on/off Refresh

/admin availability also toggles availability. A request card carries the client's name and how to reach them — the same identities the web page shows, an email marked verified or not.

Its buttons are derived from the request's status, from the same table the web page reads, so the panel never offers a move the service would refuse. Approve works on a request under negotiation too. Sending /admin again drops a half-typed answer.

Proposing a time from your phone

Propose opens on your own free times for that request; one tap sends it. If none of them suit — or you have none published — Another time opens a picker: month, then day, then hour. Times are in the practice timezone, and the message afterwards names what you sent, so a mis-tap is visible at once rather than after the client has answered it.

  • All twenty-four hours are offered. Working hours are not stored anywhere, and a guess at them would hide hours you can actually work.
  • An hour marked ✕ cannot be tapped: a confirmed or completed session starts in it, or a slot you blocked off or booked out. It stays in place rather than disappearing, so the mark reads as “there is something there” instead of as a gap.
  • A held slot is not marked. A hold lapses on its own, and it belongs to a client who has not finished a form.
  • A week that is wholly past is dropped from the day grid.
  • Type it is still there, for 18:30 and for a proposal of words only.

Only Type it parks anything. Every picker button carries the whole answer so far, so a screen left in your chat overnight still means what it said and there is no half-finished picker to abandon.

A client's own words reach you here in full — a note they added, or the time and wording they countered with — rather than as “open the request to read it”. A long one arrives split across messages.

Content, translations, settings, session types, timezones, and creating slots are web-only. The bot sends a link instead.

17. What clients experience

  • Web — your content, language switcher, booking form, email magic link (if SMTP is on) or Telegram sign-in.
  • Telegram — /start, topic menu, the same booking flow, action buttons on notifications.
  • Email — login links and “open your request page”. No meeting URL in the body.

Booking

Picking a slot does not reserve it. The page asks them to finish inside the slot-hold window and says plainly that the time is not held until they submit — two people can be looking at the same slot until one of them does.

A signed-in client gets their name filled in, and the contact note from their last request offered back. Typing an address into the form signs nobody in: the session and the Telegram link both wait for the emailed link, which only the owner of that address can read. The booking itself goes through either way, and a sign-in link is emailed with it.

Answering your proposal

On the request page and in the bot: Accept, Decline, and a way to suggest another time — your own free slots as buttons first, in their timezone, filtered exactly as the booking picker is. One tap gives you something you can approve in one click. Beneath them, where free text is allowed, a date picker and a note.

In the bot it is the same three screens — month, day, hour — in their language and their own timezone, behind the free slots. It shows nothing about your diary: marking your filled hours would tell a client when other people have sessions, and quietly omitting them would say the same thing by the gap it left. So a client can suggest an hour you already have something in; you decline or propose again, which is an ordinary round trip. Two months ahead rather than three, because a time four months out is not one you can act on.

A counter reserves nothing. The slot is checked again when they submit, so a page left open for an hour cannot hand you a time you no longer offer.

Free text is capped at 4096 characters, shown on the field as they type. Over-long text is refused rather than quietly shortened.

A web client can later tap a Telegram deep link in email to attach Telegram to the same person.

19. Troubleshooting

The dot in the top bar

Every admin page carries a small coloured dot. It links to /admin/status, which lists what the service checks about itself.

  • Green — nothing to do.
  • Amber — something will break soon (backups have stopped, disk filling up). Not urgent today; do not leave it a month.
  • Red — clients are affected right now. Open the page, read the plain sentence, and call whoever runs your server. Each check also shows a technical line written for them — read it out or send a photo of it.

The dot never counts your own workload. Ten unanswered requests is work, not a fault, and it stays green.

If something goes red you also get a Telegram message, so you do not have to be looking at the page. One message per fault, not one per minute.

A green dot means everything inside the server is fine. It cannot tell you the site is reachable from outside — ask whoever runs the server to set up an external check on /readyz.

20. Notes for whoever hosts the server

Ordinary therapist work never needs a shell.

Set once in .env: admin login, Telegram bot token / username / webhook secret / admin IDs, SECRET_KEY, BASE_URL, database password, optional SMTP, and DOMAIN+ACME_EMAIL only for the TLS profile.

docker compose logs -f web worker
docker compose logs backup
ls -la backups/
docker compose stop web worker
docker compose exec -T db pg_restore -U "$POSTGRES_USER" -d "$POSTGRES_DB" --clean --if-exists < backups/psychobooking-YYYY-MM-DD.dump
docker compose start web worker
git pull
docker compose up -d --build

Take a dump before upgrading. web migrates before it serves traffic.

21. What this product is not

  • Not payments or invoicing
  • Not a multi-therapist clinic roster
  • Not clinical notes or homework
  • Not Google Calendar / CalDAV sync
  • Clients cannot cancel their own bookings

It stores what is needed to schedule a session, and as little else as possible.

Shipped with the service. This page is served from your own installation at /admin/help, so it always matches the version you are running.
